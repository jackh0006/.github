# Contributing

Thank you for improving these projects.

## Workflow

1. Open an issue for a bug, security concern, or feature proposal.
2. Fork the repository and create a focused branch.
3. Keep changes small and include tests or verification steps.
4. Follow the repository's formatting and lint rules.
5. Open a pull request with a clear summary and risk notes.
6. Do not include secrets, private keys, recovery phrases, or live credentials.

## Security issues

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md).

## Review

Pull requests are reviewed for correctness, security impact, compatibility, and documentation. A passing CI run is required before merge.
