# Security Policy

## Reporting a vulnerability

Report security issues privately to **jackh109867@gmail.com**.

Do not open a public issue for a suspected vulnerability. Include:

- the affected repository, version, or commit;
- a concise description and impact;
- safe reproduction steps using throwaway keys and a test network;
- any suggested mitigation.

Never send a recovery phrase, private key, password, vault file, or live credential.

## Scope

This policy covers repositories owned by **jackh0006**. Each project may publish additional scope, threat model, and supported-version details in its own `SECURITY.md`.

## Disclosure

Reports are acknowledged privately. The maintainer assesses impact, prepares a fix, and coordinates disclosure with the reporter.

## Supported versions

Each project documents its supported versions. Use the latest signed release and verify checksums before installing.
